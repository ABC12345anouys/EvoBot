# StepPlanner 架构：可插拔小模型 + 步级快照重试

> 动机（2026-09-23）：一下午的 30/30 攻坚实证了 hard-code 路线的边界——
> z_top 角点公式、straddle 方向、contact_stop_band 值，每个修复都是场景
> 特例，修一个过一个、换一个场景再破。和自动驾驶 hard code 被证明无法
> 覆盖长尾完全同型。本文档把系统重新分解为：**每一步的参数由"当时情况"
> 经一个可插拔的小模型给出；失败回滚到该步快照原地重试（≤5 次）；超限
> 失败做归因分析**。机器人低速、可重试，这是相对自动驾驶的结构性优势，
> 架构必须把它变成一等公民。

## 0. 设计原则

1. **泛化 = 小模型边界的并集**。整体泛化不来自任何单一大模型，而来自
   每个决策点上的小模型各自在自己的特征空间内泛化（k-NN 在相似几何间、
   解析模型在形状参数空间内、LLM 在语义层内）。组合即整体能力。
2. **脚链 = 约束层，不是策略**。物理约束（碰撞/限位）、安全约束
   （PARAM_SPEC 范围、anchor 邻域）、预算约束（重试 ≤5）对一切策略生效；
   策略在约束内自由——戴着脚链跳舞。
3. **已验证的东西全部保留**。现有规则/几何/配置成为注册表的 fallback
   策略与先验，新架构包裹旧系统，不是推倒重来（见 §6）。
4. **重试是一等公民**。每个 skill 步独立快照、独立预算、独立归因。

## 1. 总体结构

```
┌────────────────────────────────────────────────────────────┐
│ 约束层 Constraints（物理/安全/预算，一切策略不可违反）        │
├────────────────────────────────────────────────────────────┤
│ 参数策略层 Parameter Policies（可插拔小模型，per-step 调用） │
│   grasp_pose │ descent_depth │ approach_dir │ obstacle_     │
│   margin │ place_gain │ timeout │ retry_explore │ ...       │
│   每种策略有若干实现：rule │ geometry │ knn │ linear │ llm   │
├────────────────────────────────────────────────────────────┤
│ 重试与记忆层 Retry & Memory                                 │
│   步前快照 → 执行 → 失败回滚该步 → 换参重试(≤5) → 归因入库   │
├────────────────────────────────────────────────────────────┤
│ 执行层 Skills（现有原子技能不动，参数全部改为注入）           │
│   above/descend/close/lift/carry/place/...                  │
└────────────────────────────────────────────────────────────┘
```

与现状的关键差异：**参数在每一步执行前由 policy 现场生成**（closed-loop），
而不是 episode 开头 adapt_cfg 一次、整轮尝试用同一组参数（open-loop）。

## 2. 核心接口

```python
class StepContext:
    """policy 的输入：当时的情况。"""
    step: str                    # "descend" | "carry" | "place" | ...
    features: dict               # 几何特征（真值）：bounds、障碍 AABB、
                                 # 夹爪指宽、目标容差、相对位姿……
    attempt: int                 # 本 episode 第几次尝试
    retry: int                   # 本步第几次重试（0=首次）
    fail_history: list[FailRecord]  # 本步前几次重试的失败分类+遥测
    memory: EpisodeMemory        # 跨 episode 的相似情形库
    cfg: dict                    # per-env 底参（anchor，安全邻域中心）

class StepPolicy(Protocol):
    name: str                    # "rule" | "geometry" | "knn" | "llm" | ...
    def propose(self, ctx: StepContext, param_space: ParamSpace) -> dict:
        """返回该步参数：{point, z_target, margin, gains, timeout, ...}
        必须落在 param_space（约束层）内；超出被裁剪并记录。"""

class ParamSpace:
    """约束层的显式表示：每个参数的范围/锚定邻域/离散档。"""
    def clip(self, params: dict) -> tuple[dict, list[str]]: ...
```

注册表（可插拔的落点）：

```python
POLICY_REGISTRY = {
    ("grasp_pose",   "rule"):     RuleGraspPose(),      # 现状：容器 Y 偏置+净空翻向
    ("grasp_pose",   "geometry"): GeometryGraspPose(),  # 现状：z_top 角点/顶点
    ("grasp_pose",   "knn"):      KNNGraspPose(k=5),    # 从 episode 记忆学
    ("descent_depth","rule"):     RuleDescentDepth(),   # 现状：z_top - z_delta
    ("obstacle_margin","rule"):   RuleMargin(),         # 现状：stall→+0.05
    ("retry_explore","rule"):     JitterExplore(),      # 现状：jit 抖动
    ("retry_explore","gp"):       BayesOptExplore(),    # 小模型：高斯过程选下一组参数
    ...
}
# per-env YAML 只声明用哪个实现： grasp_pose: {policy: knn, fallback: rule}
```

**每个决策点独立选模型**——这正是"泛化边界拓展到小模型边界"的落地：
容器抓取深度用解析模型（形状空间泛化），放置增益用 k-NN（相似场景泛化），
语义层面的方法选择才用 LLM。

## 3. 步级快照重试

现状的 resume 是"失败后回退上一个成功 skill、全局重跑后续链"——粒度粗、
浪费尝试预算。升级：

```python
class StepExecutor:
    def run(self, step, ctx) -> StepResult:
        for retry in range(5):                      # 预算约束
            snap = save_physics()                   # 已有 physics_checkpoint
            params = POLICY_REGISTRY[step].propose(ctx.with_retry(retry))
            params = CONSTRAINTS.clip(params)       # 脚链
            result = SKILLS[step].execute(**params)
            if result.success:
                return result
            restore_physics(snap)                   # 原地回滚
            ctx.fail_history.append(classify(result))   # 现有 _FAIL_KEYWORDS
            MEMORY.log(step, ctx.features, params, result)
        return Failure(attribution=analyze(ctx.fail_history))  # 归因后向上传播
```

- **原地重试**：只重跑失败的那一步，不重跑前面已成功的链（现状 resume
  重跑整条链，一次 place 失败要把 grasp/lift/carry 全部重来）。
- **换参重试**：retry>0 时 policy 拿到 fail_history，必须给出与之前不同
  的参数（exploration 也是可插拔的：jit 抖动 / 网格扫描 / 贝叶斯优化）。
- **5 次归因**：`analyze()` 比较 5 组参数×结果的遥测（progress 分类、
  接触力轨迹、clearance），输出结构化归因（不可达/摩擦不足/被遮挡/
  参数方向性错误），写入 episodic memory——这是给参数策略层的训练信号。
- 重试间世界可能已被扰动（物体碰歪）：快照恢复保证"当时情况"一致，
  这是仿真相对真实机器人的额外红利，架构上鼓励"敢重试"。

## 4. 记忆与闭环

```
episode 日志（现有 jsonl）→ 特征化 → EpisodeMemory
     │                                    │
     │  检索相似情形 (k-NN 特征距离)         │  归因标签
     ▼                                    ▼
  policy.propose(ctx) ←───────── 离线训练/在线更新小模型
```

- 今天的 `logs/episodes/*.jsonl`（几千条 attempt）直接是第一批训练数据：
  特征 = 物体 bounds/障碍布局/夹爪几何，标签 = 成功参数 vs 失败参数。
- 小模型从最简单的开始：k-NN（相似几何 → 用历史最优参数）、线性
  （参数 = w·特征，岭回归）、必要时小 MLP。**不用 VLA**——决策是低维
  连续的（几个参数），小模型足够，且可解释、可约束、可热替换。

## 5. 与自动驾驶的关系（用户问题的对照）

- 自动驾驶确实在走同一条路：端到端之前的 modular autonomy（感知/预测/
  规划各自 ML 化）、以及现在的 hybrid（端到端 + 规则安全壳）就是"小模型
  分解 + 约束层"的思路；业界教训（hard code 覆盖不了长尾）与你的判断一致。
- 机器人有两个结构性优势，架构上要用足：
  1. **低速** → 每一步可以"想"（policy 推理成本不是瓶颈，可以用稍贵的
     模型/检索）；
  2. **可重试** → 探索是免费的增量数据（自动驾驶撞了就是事故，机器人
     撞了是教学样本）。重试 + 归因 + 记忆 = 在线学习闭环。
- 行为树（BT）的 Recovery 节点、TAMP 的 replanning、"learning to retry"
  文献与 §3 同型，但本设计把重试粒度细化到 skill 步、并把换参策略化。

### 5.1 为什么自动驾驶不用整套方案？（2026-09-23 补）

前提校正：自动驾驶**用了这套方案的前一半**——MPC 本身在车载规划里
已是标配（轨迹跟踪、约束下的凸优化求解，10-50Hz 在线运行）；"端到端 +
规则安全壳"的混合架构就是本文档的"小模型分解 + 约束层"。用不了的
是后一半，四个结构性原因：

1. **重试不可逆**。机器人撞了 = 教学样本，`restore_physics()` 免费；
   车撞了 = 事故，真实世界没有快照回滚。仿真里重试一万次也覆盖不了
   真实长尾——因为真实事故恰恰发生在 sim 没建模到的地方。
2. **时间尺度**。车载控制周期 10-100ms，没有"每一步想想"的预算；
   机器人一步几秒，per-step policy 推理才负担得起。这正说明 §5 说
   的"低速"红利不是锦上添花，是架构前提。
3. **长尾不在物理，在行为**。车的物理约束（摩擦圆、运动学自行车模型、
   碰撞）早已解析且已用进 MPC；自动驾驶的长尾是他车意图、异形场景、
   交规博弈——物理约束方程压缩不了这个搜索空间。机器人的长尾恰好在
   物理参数（μ、几何、质量）里，所以"物理约束声明"（§11）对机器人
   的杠杆远大于对车的。
4. **认证与责任**。ISO 26262（ASIL-D）要求可验证性，"在线学习 +
   champion-challenger 热替换策略"在量产车里是合规灾难；机器人（尤其
   仿真环境）没有这道闸门。

一句话：**§11 的约束层两车通用，§3 的重试层只有机器人玩得起**——
这不是自动驾驶想不到，是它的物理条件（速度、不可逆性、长尾位置、
监管）把这条路堵死了。

## 6. 保留现状的映射（重要）

| 现有资产 | 在新架构中的位置 |
|---|---|
| 原子 skills（ik_servo/close/lift/carry/place） | 执行层，不动 |
| `reflection.py` 全部规则 | 各 policy 的 `rule` 实现 + fallback |
| per-task YAML 学参 | rule 策略的初值/prior；anchor 邻域中心 |
| z_top 角点/顶点几何 | `geometry` 策略实现（已验证，直接注册） |
| 容器 Y 偏置 straddle + 净空翻向 | `rule: grasp_pose` 实现 |
| avoidance 绕障 / stall fail-fast | `rule: obstacle_margin` / 执行层能力 |
| anchor / 滞环 / 防漂移守卫 | 约束层（Constraints，一切策略之上） |
| episode jsonl 日志 | EpisodeMemory 的原始数据源 |
| IPC sim_worker/agent_learner 双进程 | 进程结构不动；StepExecutor 在 agent 侧 |
| LLM 反思 | 降为 `llm` 策略实现，只管语义层（方法选择/归因解释） |

**迁移策略**：Phase A 把执行层参数来源从 cfg 直读改为 policy 调用，但所有
policy 注册为 `rule`（=今天的逻辑，逐函数搬运，行为不变、回归可测）——
这一步完成后系统行为与现状完全一致，但插槽已就位。之后逐个决策点换/加
小模型，每换一个跑全量回归（verify_30），这就是"戴着脚链跳舞"的工程版。

## 7. 分期落地

- **Phase A（骨架，行为不变）**：StepContext/StepPolicy/ParamSpace/
  Registry + 把 adapt_cfg 的调用点改为 per-step propose（全 rule 实现）。
  验收：verify_30 分数与迁移前完全一致。
- **Phase B（快照重试，与 A 并列最高优先级——§13.1-3：6 个失败任务里
  3 个的公共解）**：StepExecutor + 步级 physics 快照 + 5 次预算 +
  归因分析。替代现有 resume 粗粒度回退。验收：单个 place 失败不再重跑
  grasp/lift/carry；失败任务尝试预算利用率显著提升。
- **Phase C（第一个学习小模型）**：grasp_pose 的 `knn` 实现（用现有
  episode 日志离线构建记忆库），在 4 个 akita_black_bowl 任务上对比
  rule/knn 的成功率。这是"泛化边界拓展"的第一个实证点。
- **Phase D（语义层 LLM + 归因语言化）**：归因输出自然语言总结，
  辅助人工分析与 skill 库扩展决策。

## 8. 风险与边界

- 小模型的天花板：特征设计决定泛化半径（garbage in, garbage out）。
  缓解：特征用真值几何（仿真红利），且 rule fallback 兜底——任何小模型
  提议劣于 fallback 时被约束层否决（champion-challenger 评估）。
- 快照恢复掩盖世界随机性：重试学到的东西在真实扰动下未必成立。
  缓解：memory 记录"重试成功所需次数"作为参数稳健度指标；稳健的参数
  优先（一次成功 > 五次侥幸）。
- 复杂度：插拔点过多会导致配置矩阵爆炸。缓解：默认全 rule，只有数据
  证明小模型更优的决策点才开放插拔（champion-challenger 数据驱动）。

## 9. 编码 Agent 接入（Codex / Claude Code / Kimi Code）

> 动机：开发、调参、回归、写 skill 是 token 大户且高度机械。让编码
> agent 直接进工作区干活，主系统只保留"任务卡进、结论出"。

### 9.1 目标
- **无缝衔接**：接到 codex / claude code / kimi code 任一，开箱直接做
  任务，无需人肉复述上下文。
- **省 token**：主循环不贴 log、不贴代码，过程 token 全部隔离在子
  agent 的独立 context 里。

### 9.2 机制
- **workspace 共享 + 文档即记忆**：仓库内 docs/（本文档、AGENTS.md、
  SKILL.md）就是跨 agent 的长期记忆。任何 agent 进来读文档即恢复上下
  文——与 §4 EpisodeMemory 同构：机器人对场景的记忆 ↔ agent 对代码库
  的记忆。
- **任务卡交接**：主系统给子 agent 的只有结构化任务卡——目标 / 涉及
  文件 / 验收命令（如 verify_30），不给历史过程。子 agent 的失败重试
  在内部消化，只回传结论 + 证据（diff、测试输出）。
- **headless 执行器**：各 CLI 的非交互模式包一层统一执行器
  `dispatch(任务卡) → {结论, diff, 验收结果}`，可插拔，与 §2 注册表同型。
- **上下文隔离 = 省 token**：主 agent 只为任务卡和结论付费，约为"主循
  环亲自做 + 人肉搬运上下文"的几分之一（待实测，写进验收）。
- **失败升级**：子 agent 约定次数未完成 → 升级回主系统归因（复用 §3
  归因分类：不可达/信息不足/验收不清），归因写入任务卡模板库，越用越准。

### 9.3 验收
- 新 agent 空上下文进入仓库，只读 docs/ 即完成一次 step 参数调优任务；
- 该任务主循环付出的 token < 主循环亲自做的 20%。

## 10. 陌生任务 ≤N 次尝试学会、与类任务泛化（含 gap 分析）

> 动机：面对陌生任务希望"试 ≤10 次就会做"，乃至泛化到一类任务。
> 现有架构支撑其中一半，另一半是 gap，如实记录。

### 10.1 架构已支撑的部分
- 步级重试预算（§3）把"试 10 次"工程化：每步 ≤5 次 × 多步 ≈ 任务级
  10+ 次探索，每次换参、每次归因入库。
- EpisodeMemory（§4）让同类任务第 11 次不用从零开始：检索相似情形直
  接给先验参数。

### 10.2 Gap（为什么不能保证泛化）
1. **单场景搜索 ≠ 类泛化**。10 次尝试学到的是"这个物体在这个位置的参
   数"，换物体/换布局可能失效。泛化要求特征抓住跨场景不变的因果量
   （接触几何、摩擦、质量分布），而不是场景特异的坐标——这正是 §8
   "特征设计决定泛化半径"的另一种说法。
2. **成功信号是弱监督**。只知道成功/失败，不知道差多少；credit
   assignment 靠 §3 的遥测归因补，归因质量决定学习上限。
3. **覆盖维度**。一类任务的自由度（形状 × 姿态 × 摩擦 × 遮挡）可能超出
   10 次探索能覆盖的角落；未覆盖的角落 = 长尾，与自动驾驶同型。
4. **已有防御**：rule fallback + champion-challenger（§8）——小模型学
   不会时退化到规则，系统不会比现状差。

### 10.3 设计含义
- 尝试预算做成 per-step 可配置（默认 5），任务级预算 = Σ step 预算，
  写进约束层（预算约束本来就是约束层的一员）。
- "学会"的判据不是"这次成功"，而是"memory 中该类特征的最近 k 次成功率
  > 阈值"才允许该类任务摘掉 fallback——数据驱动开放插拔，同 §8。
- 新 skill 上线前先做变异测试：同任务换实例 ×N，作为类泛化的实证指标。

## 11. 从 hard-code YAML 到可反推的物理约束

> 动机：per-task YAML 参数表是 hard code——LLM 拿到 `descent_depth:
> 0.12` 不知道 0.12 从哪来，无法在新场景反推。目标：YAML 从"答案表"
> 变成"约束声明"，模型从场景特征现场推导参数。以下问题经 web 调研
> 回答（2026-09）。

### 11.1 有什么物理约束方程？

刚体操作任务里约束方程存在且成熟，全部可解析、可在线求值：

| 约束类 | 方程/判据 | 用途 |
|---|---|---|
| 运动学/工作空间 | IK 有解、关节限位、避奇异 | 可达性预检 |
| 碰撞 | signed distance ≥ d_min（AABB/凸包/GJK） | 位姿与路径可行 |
| 接触 | 法向力 f_n ≥ 0（单向不粘合） | 接触合法性 |
| 摩擦 | Coulomb 锥 ‖f_t‖ ≤ μ·f_n | 抓起后是否滑落 |
| 抓取稳定 | 力封闭/形封闭，grasp wrench 空间含外力螺旋 | 抓取成功下限 |
| 放置稳定 | 质心投影 ∈ 支撑多边形 | 放置不倒 |
| 几何尺寸 | 夹爪开口 ≥ 物体宽 + margin | 闭合可行性 |

文献佐证：LLM 在 3D 空间做动作推理时显式编码接触/支撑等物理约束
（[ActionReasoning](https://arxiv.org/html/2602.21161v1)）；closed-loop
状态反馈 + 物理可行性检查的分层 LLM 规划
（[Grounding LLMs with Closed-Loop State Feedback](https://advanced.onlinelibrary.wiley.com/doi/10.1002/adrr.202500072)）；
把物理因素显式喂给 LLM 改善操作
（[LLM with Physical Factors, TAROS 2025](https://eprints.whiterose.ac.uk/id/eprint/228303/1/TAROS_2025_Poster_110.pdf)）。
**结论：方向可行，且是当前文献热点。**

### 11.2 和 MPC 有区别吗？

有本质区别，但本架构离 MPC 只差一步：

- **MPC** = 动力学模型 + 代价函数 + 固定时域滚动优化，每个控制周期
  在线求解；约束只是优化问题的可行域。代表做法如 VLMPC：LLM 提供目
  标与约束，MPC 求解底层控制
  （[VLMPC, RSS 2024](https://www.roboticsproceedings.org/rss20/p106.pdf)）。
- **本架构的约束层**（§2 ParamSpace.clip）= 无优化、无动力学 rollout
  的**可行域投影**：policy 提案 → 约束裁剪 → 执行。是"过滤"，不是
  "规划"。
- 关系：§1 的 per-step closed-loop（每步重看情况、重新 propose）本质
  是 **horizon=1 的 MPC 骨架**；把 propose+clip 换成"对未来 h 步做约
  束优化"即退化为标准 MPC。演进路径清晰，但当前不需要——低速 + 步级
  重试已拿到闭环收益的大半，h>1 的优化留给以后有明确收益再上。

### 11.3 物理约束方程能通用吗？

**部分通用，有四个前提裂缝：**

1. 刚体假设下，上述方程对一切刚体任务通用（抓、放、推、堆叠）。
2. **参数不通用**：μ、质量、质心、刚度必须在线辨识，估错则约束求值错。
3. **软体/液体/可变形物体**（布料、倒液体）超出刚体方程覆盖，需要另
   一类模型——不在本架构第一阶段范围。
4. **感知噪声**：约束输入（位姿、bounds）本身有误差，约束满足 ≠ 物理
   满足（d_min 加安全裕度就是为了这个）。

### 11.4 约束能泛化到所有情况、保证任务成功吗？

**不能，写进设计假设：**

- 约束保证的是**可行/安全**（不碰、不超限、不立即滑落），不是**成功**。
- 集合关系：`{约束满足} ⊂ {任务成功}`。满足摩擦锥仍可能因未建模动力学
  滑落；满足支撑多边形仍可能被后续步骤碰翻。
- 任何"保证"只在**模型准确 + 参数准确 + 刚体假设成立**三者同时成立时
  成立——真实世界三者全中的概率不高，这正是 sim2real gap 的根源。
- 正确定位：**约束层把搜索空间从全参数空间压缩到物理可行集；成功靠
  §3 重试 + §4 记忆在可行集内逼近**。约束负责"不犯物理错误"，学习负
  责"越来越会选"。

### 11.5 落地：YAML 从"答案表"到"约束声明"

不改执行层，只改参数来源的声明形式：

```yaml
# 现在（答案表，hard code，LLM 无法反推）
descent_depth: 0.12

# 目标（约束声明：参数 = f(场景特征)，LLM/策略可现场推导）
descent_depth:
  derive: "z_contact - margin"
  from:   [target_bounds.z_top, gripper.finger_width]
  clamp:  [0.02, 0.30]        # ParamSpace 物理上下限
```

- 每个参数声明三要素：**推导式**（物理来源）、**输入特征**（从
  StepContext 取）、**物理夹紧域**（ParamSpace）。
- rule policy 就是这些推导式的代码化；knn/llm policy 在约束声明给定
  的流形内搜索，而非全空间瞎搜。
- LLM 的角色从"查表填值"变成"读约束声明 + 场景特征 → 推参数"——这
  正是"根据场景反推"；约束声明同时是跨 agent 文档（接 §9，编码 agent
  读同一套声明做调参）。
- 分期：Phase A 行为不变；Phase C 起新 YAML 只写约束声明，旧答案表由
  迁移包装成 `derive: const(0.12)` 过渡，随 champion-challenger 数据逐
  个替换成真推导式。

## 12. 能力层：模型注册表与"没有对应小模型"的路径

> 动机（2026-09-23）：§2 解决"参数谁来给"，但陌生任务进来时更前面的
> 问题是"它需要哪些感知/推理能力、手头有没有模型"。现状是每个感知
> skill 各自硬编码 model+fallback，缺统一注册表和缺模型的标准路径。

### 12.1 现状盘点（2026-09 代码审计）

真实加载的模型只有 4 个，且多数是"仿真真值的备胎"：

| 能力 | 模型 | 位置 | 评价 |
|---|---|---|---|
| 检测 | YOLO26n（COCO 闭集） | perception/detect.py | 真模型；查不到时静默回退真值 `_gt_detect()` |
| 分割 | MobileSAM | perception/segment.py | 真模型（prompt 来自 YOLO bbox） |
| 抓取位姿 | GraspNet baseline | perception/grasp.py | 真模型；缺权重时回退 PCA 几何法 |
| 深度 | 无网络，MuJoCo 真值渲染 | detect.py EstimateDepthSkill | **仿真专用**，真实相机只有占位 |
| 点云 | 无模型，geom 顶点采样 | grasp.py | 纯几何，仿真红利 |
| 6D 位姿 | 无网络，全部真值 | — | **仿真专用** |
| LLM 规划 | 远程 API（Ark/OpenAI 兼容） | llm/client.py | 真；无 key 回退 OfflinePlanner |
| RAG embedding | TF-IDF（可选 MiniLM） | memory/rag.py | 默认无模型 |

另外权重镜像表里躺着的 `yolo26n-depth.pt` / `sam_b.pt` / `FastSAM-s.pt`
**零代码引用**——下载了没接。

结论：**跑仿真基准足够（兜底全是真值），但模型层真实覆盖比看起来薄得
多**。一旦上真机，深度/位姿两条真值回退同时消失，系统失明。

### 12.2 能力注册表（与 POLICY_REGISTRY 平行的新层）

```python
CAPABILITY_REGISTRY = {
    "detect":     {model: YoloDetect(),    fallback: GTDetect(),      status: "real"},
    "segment":    {model: MobileSAMSeg(),  fallback: BoxShrinkSeg(),  status: "real"},
    "grasp_pose": {model: GraspNet(),      fallback: PCAGrasp(),      status: "real"},
    "depth":      {model: None,            fallback: GTDepth(),       status: "sim-only"},  # 缺口
    "pose6d":     {model: None,            fallback: GTPose(),        status: "sim-only"},  # 缺口
    "open_vocab": {model: None,            fallback: None,            status: "missing"},   # 缺口
    "vlm_scene":  {model: None,            fallback: TextSceneGraph(),status: "missing"},   # 缺口
}
```

- skill / policy 声明自己需要哪些 capability，由注册表统一供给，**禁止
  skill 私下 torch.load**——收敛 detect/grasp/segment 各自加载的现状。
- **fallback audit 进回归**：统计每任务落到 fallback 的能力比例；fallback
  率超阈值的即"名义上有、实际靠真值"，进缺口清单。这是上真机前
  readiness 的硬指标。

### 12.3 缺模型的标准决策路径（"没有对应小模型怎么办"）

逐能力查注册表，按优先级四条路：

1. **几何/规则兜底**（已有）：能解析推导就不学——§11 约束声明优先于
   任何模型。
2. **换等价基础模型**：同一能力有多个现成基础模型可插（§12.4），注册表
   换一个 key 即可；选型判据是 champion-challenger（§8）。**模型不是越
   多越好，每个常驻模型都是显存/延迟/维护成本**。
3. **LLM 语义近似**：语义层能力（能不能抓、从哪侧接近）交给 LLM + 场景
   图文本推理，物理夹紧域（§11）保证不出格。LLM 是永远在线的通才备胎。
4. **标记缺口 → 收集数据 → 事后补模型**：走不通的能力打 missing 标签，
   由 §3 归因 + §4 EpisodeMemory 自动积累特征-成功数据——这正是 §10
   "试 10 次学会"的数据来源；攒够后按 §4 训练/微调，注册进表，缺口关闭。
   **缺模型不是异常，是 learning loop 的输入。**

关键设计点：1→4 的降级路径本身文档化，LLM/编码 agent（§9）读注册表即
知任何任务当前能靠什么完成、缺什么，而不是各 skill 隐式各自翻车。

### 12.4 基础模型全景与缺口对照（2026-09 web 调研）

按[基础模型操作综述](https://arxiv.org/html/2404.18201v7)的分层对照：

| 层 | 代表模型 | 状态 | 优先级 |
|---|---|---|---|
| 闭集检测/分割 | YOLO26n / MobileSAM | 已有 | — |
| 开词汇检测/分割 | Grounding DINO / OWL-ViT / SAM2 | 缺（YOLO 是 COCO 闭集，物体一换就瞎） | 高——真机第一步 |
| 深度/3D | DepthAnything-V2 / VGGT 类；`yolo26n-depth.pt` 已下载未接 | 仿真真值顶着 | 高——先把已下载权重接上 |
| 抓取 | GraspNet | 已有 | — |
| 语义/VLM | VLM API + CLIP embedding | 缺（LLM 只看文本场景图） | 中——§11 约束反推的输入源 |
| 6D 位姿 | FoundationPose 类 | 缺（全真值） | 中——抓特定物体时需要 |

"模型尽可能多"的正确形态不是堆数量，而是**每层恰好一个 champion +
注册表可换**。当前最划算的四个动作：① 接上已下载的 yolo26n-depth.pt；
② 引入开词汇检测换掉 COCO 闭集瓶颈；③ 深度/位姿的 GT fallback 加
audit 告警；④ RAG embedding 从 TF-IDF 切到本地小模型。

### 12.5 分期

- Phase C 同期：CAPABILITY_REGISTRY 骨架 + fallback audit（只观测，
  不改行为）。
- Phase D：接开词汇检测 + depth 权重；missing 标记进 EpisodeMemory。
- 真机 readiness 门槛：fallback 率归零才允许切真机相机。

## 13. 六个失败任务 → 架构机制对照（2026-09-23 攻坚实证）

> 24/30 后剩余 6 个失败任务，每个都精确定位了机制。它们不是 6 个孤立
> bug，而是 6 个"hard-code 边界"的标本——正好逐一检验本架构的机制是否
> 覆盖。结论：**6 个全部可被架构机制攻克，但其中 3 个暴露了文档原版的
> gap，已按下表补充进 §2/§3/§11**。

| 任务 | 实证根因 | 攻克它的架构机制 | 修订点 |
|---|---|---|---|
| spatial:4 | descend 停在沿口上方 22mm、全程零接触——不是几何阻挡，是**下降速率×步数预算**不够（YAML timeout_scale/kd 是历史拍脑袋值） | ① `timeout` 成为 policy 参数：`derive: f(距离, vcap, 收敛速率)`（§11 约束声明）；② 步级重试：换 kd/vcap 重试不重跑全链 | **新增**：StepContext 加 `progress_rate` 遥测（eef z 轨迹斜率），停滞分类器用真速率而非步数拍脑袋 |
| spatial:9 | grasp→carry 全通，死在 **place slipped**（夹持力/物重摩擦边际） | ① 摩擦锥约束（§11 已有）落到 place：`place_vcap/grip_force derive: f(μ, m, F_grip)`；② **Phase B 步级快照**：place 失败原地重试，不重跑 grasp/lift/carry（现状 resume 粗粒度把预算烧在前面） | 无新机制，**Phase B 优先级提升**——它是 spatial:9/goal:2/goal:8 的公共解 |
| goal:2 | 同 spatial:9（酒瓶 place slipped 8/8） | 同上 | 同上 |

### 13.1 从 6 个标本提炼的 4 条架构修订

1. **一切静默 fallback 都是 bug 种子**（goal:5 的教训）：任何"模型没产出
   → 偷偷用几何/真值/默认值"的路径必须计数 + 告警 + 进 fallback audit。
   champion-challenger 的前提是知道什么时候在用 challenger。
2. **预算参数也是参数**（spatial:4 的教训）：timeout/kd/vcap 和抓取点一
   样是"根据当时情况推出"的量，进 §11 约束声明（`derive:` 三要素），
   不允许 YAML 裸值当答案表——这正是 §11.5 要消灭的东西的第一个实证。
3. ** Phase B（步级快照重试）是 6 个任务里 3 个的公共解**，从"Phase B
   排在骨架之后"提升为与 Phase A 并列的最高优先级：不改它，place 类
   失败的每次尝试都在为前面已成功的步白付费。
4. **接近段是与 descend/carry 同级的独立决策点**（goal:3/4 的教训）：
   "到得了起点"和"起点选得对"是两个独立小模型各自的泛化边界，混在
   一个 ik_servo 里只能靠全局参数一起调，互相干扰。

## 14. 分层物理约束：机器人无关的泛化层（2026-09-23）

> 动机：§11 解决了"参数要有推导式"，§13 用 6 个失败任务实证了"裸数值
> 不泛化、推导式泛化"。本节回答下一层问题：推导式本身能不能总结成
> **一套与机械臂无关的约束全集**——抓、放、推、插、堆、开关节体共用。
> 结论：能。这套东西在文献里有根基（Mason 的顺从操纵、Lynch & Mason
> 稳定推动、TAMP 的谓词+连续约束），本架构的角色是把它 operationalize
> 成代码里的单一来源。

### 14.1 三层模型

```
L0 物理定律（无条件通用）
   刚体、摩擦锥 ‖f_t‖ ≤ μ·f_n、法向接触单向、重力
L1 任务约束（机器人无关 ← 泛化的主体）
   以"物体×环境"为中心的关系式，不含任何机械臂变量、不含世界坐标
L2 机械臂适配层（唯一与臂有关的部分，必须很薄）
   只做投影/过滤：IK 可达、臂关节限位、力矩上限、夹爪几何（指距/指宽）
   策略（rule/knn/llm）住在 L1；L2 把 L1 的可行集投到具体臂的工作空间
```

关键性质：**策略可以蠢、可以错，但物理上不可能的执行永不发生**
（`{约束满足} ⊂ {任务成功}`，§11.4）。L2 换臂即换，L0/L1 原封不动。

### 14.2 L1 约束全集（按动作）

| 动作 | 机器人无关约束 | 失效边界（诚实标注） |
|---|---|---|
| 抓 | 力封闭/形封闭：grasp wrench space 含重力螺旋；摩擦锥内可施加夹持力 | 软体/可变形物；μ 未知时只能给裕度版 |
| 放/堆 | 质心投影 ∈ 支撑多边形；放置面共面 | 质心不可从几何推出（需在线辨识/记忆库） |
| 推 | 稳定推动条件：推点位置、摩擦角、运动前向锥（Lynch & Mason） | 多接触推挤（ clutter 深堆）退化需搜索 |
| 插 | 间隙比 + 倒角捕获：轴对正 ∧ 间隙 > 姿态误差 → 力控可收敛 | 深孔长径比过大 → 需多段对准（仍然同型约束叠加） |
| 笼取 | 物体全部逃逸方向被几何封闭（caging） | — |
| 开关节体 | 关节轴方向 + 限位 + 把手可达点 + 拉力/力矩沿轴 | 多关节链（柜门+抽屉联动）需逐关节串接同一约束 |

覆盖性：LIBERO 30 任务 + LIBERO-10 的抓放推插开柜全部落在表内。
**覆盖边界**：刚体操作。布料、倒水等可变形/流体不在 L1 内，属另一类
模型（§11.3 前提裂缝 3）。

### 14.3 三条工程规则（把"L1 可泛化"变成"代码可泛化"）

1. **约束用物体中心坐标系写，禁用世界坐标**。不说 "z=1.115"，说
   "沿口上方 22mm"；不说 "往 y-0.18 抓"，说 "沿口径向 0.7×半高处
   straddle"。straddle 推导是范本——全文无场景坐标，所以 spatial:2/9
   通用；z_delta=0.042 那种写法天生不可移植。
2. **技能用约束参数化，不用轨迹参数化**。"下降到接触"而非"下降 90 步"；
   "沿关节轴拉到限位"而非"回放 demo"。轨迹是彩票，约束是方程。
   articulate 现状是轨迹型（demo 回放），换柜体布局即脆——升级方向见
   §14.5-P3。
3. **记忆库键 = 物体中心特征，禁止任务 ID**。"高摩擦圆柱、0.5kg 级"
   跨场景跨臂复用；"libero_goal_2 成功参数"一文不值。EpisodeMemory
   特征化时按此原则（§14.5-P2）。

### 14.4 现状审计与重构清单（file:line，按优先级）

核心病灶：**同一物理推导散落在 4 个文件、互相不同步**——所以同一条
知识有时救活任务、有时污染下一个（z_delta 踩踏的结构性根源）。

**已是对的，不动**：
- `envs/libero_adapter.py`：`object_bounds` / `articulation_info` /
  `contact_force_on_body`——L1 特征的真值来源（606 行里最值钱的 200 行）
- `envs/physics_checkpoint.py`：Phase B 快照地基，干净

**P0 — 收敛 `darwin/physics/` 引擎（四处物理 → 一处单一来源）**

## 15. 约束即知识：违背→对偶割→后验收缩（2026-09-23 二版）

> 动机：§14 给出了"什么能泛化"，但系统怎么**学得快、迁得快**的答案
> 还不够优雅——重试序列是手工表（仍是 hard-code）、学习信号是二元的
> （浪费遥测）、反思在 episode 级慢循环。本节用一个统一抽象替换这三
> 处，使学习速度接近信息论上限。

### 15.1 核心抽象：约束是知识的最小单位

```
知识 = 约束实例，不是参数值，不是任务经验
  约束实例 = (判据 predicate, 未知标量集合 Θ, 裕度 margin)
  例：抓持约束 = {‖f_t‖ ≤ μ·f_n}，Θ = {μ}，其余全部解析可得

执行 = 在约束可行集内选点（L1 给域，L2 投影，策略选点）
失败 = 约束违背（violation），不是"运气不好"
违背 → 对偶割（dual cut）：由违背的约束解析推出 Θ 上的一个半空间
学习 = Θ 后验收缩（半空间交），不是梯度下降，不是网格搜索
迁移 = 约束实例化（免费）+ Θ 残差检索（记忆库）+ 在线辨识（≤k 次）
```

为什么快：**只有 Θ 里的标量需要学**（μ、质量、质心偏差、感知偏置），
通常 k≤3~5 个；其余一切由判据解析推导。每个失败贡献**一条不等式**
（μ·F_grip < m·g → μ < m·g/F_grip），可行集单调收缩，无一步浪费。
学习速度上界：O(k) 个信息量充分的失败即可定参——比逐参数二进制
搜索（现状反思）少一到两个数量级的尝试。

### 15.2 违背分类 → 对偶割算子表（reflection 的替代物）

`reflection.py` 的十几条 if-elif 将被一张表替代——每条失败模式映射
到"哪个约束被违背"和"对应的不等式怎么写"：

| 遥测签名 | 违背的约束 | 对偶割（写进 Θ 后验的不等式） |
|---|---|---|
| lift 时物体下滑（z 不随 TCP） | 摩擦锥 | μ < m·g / F_grip（空间:9/goal:2 place slipped 的直接读法） |
| descend 零接触停住、z 轨迹匀速 | 时间预算（导出约束） | timeout < 距离/实测速率 → 预算≥距离/速率×1.3（spatial:4 的直接读法） |
| descend 接触后 z 停、xy 漂 | 几何干涉 | clearance < margin → 抓取点须移出障碍 AABB⊕margin |
| lift_no_grip F=0 | 力封闭 | 抓取构型 ∉ 封闭集 → 换候选点（几何推导，无 Θ） |
| place 后物体倾倒 | 支撑多边形 | 质心投影越界 → 放置点修正；m̂/质心偏差进 Θ |
| place_timeout TCP 到不了 | 可达性 | 目标 ∉ 工作空间投影 → 换路径点（几何，无 Θ） |

每条割带**置信度**（遥测签名越唯一越高），低置信割软更新（收缩幅度
×置信度）——防止误分类把 Θ 切错方向（本设计的头号风险，§15.6）。

### 15.3 运行时约束监视器：失败在发生的那一刻被截获

现状：skill 跑满 timeout 才报失败，一步浪费几百个仿真步，且失败时刻
的物理状态已被后续步骤污染。升级：

```
执行层每 N 步 → constraints.check(active_constraints, 实时遥测)
  违背部即刻触发：
    ① abort（不必等 timeout）
    ② 现场遥测打包成 violation record（此刻的 f_n/f_t/位姿/速度）
    ③ 走 §15.2 的割算子，更新 Θ 后验
    ④ 换参重试（从收缩后的可行集采样，§15.4）
```

收益翻倍：同样 5 次重试预算，每次失败的信息量从"超时了"变成"摩擦锥
在 F=8.1N 时被打破"——**学习信号从二元变连续**（违背时的瞬态值就是
参数估计的充分统计量）。

### 15.4 探索自动化：从可行集后验采样，删除手工序列

§3 的重试换参表（_DESCEND_SEQ 等）全部退役，替换为：

```
重试参数 = argmax_{p ∈ 可行集后验} UCB(p)        # 便宜版 BayesOpt
  可行集 = ParamSpace（§2）∩ Θ 后验半空间交
  无解析判据的残差（极少数）→ GP/ Thompson sampling
  rule 策略 = Θ 先验中心（迁移时的 day-0 起点）
```

手工表消失，"先软后慢再加时"这类拍脑袋顺序由采样自动发现——而且它
会随 Θ 后验收缩自动聚焦到真正窄的维度上（若 μ 是瓶颈，采样全花在
夹持力相关参数上）。

### 15.5 迁移的三段式（回答"迁得快"）

新任务/新场景/新臂进来，按序：

1. **实例化（0 次尝试，免费）**：从场景真值生成 L1 约束集——物体
   bounds→抓取/放置约束，关节 info→关节约束，目标几何→插装间隙
   约束。策略 day-0 就有可行域，哪怕 Θ 全用宽先验。
2. **残差检索（0 次尝试）**：Θ 在记忆库中按物体中心特征检索最近邻
   （§14.3 规则 3），若该邻居的 μ̂/m̂ 已有在线辨识记录，直接继承其
   后验而非先验——**同类物体的摩擦/质量分布是稳定的物理事实**。
3. **在线辨识（≤k 次）**：运行期每个违背割继续收缩 Θ；首个成功即
   冻结该任务 Θ 并写回记忆库（含置信度）。k 个未知标量 ⇒ 理论上
   k 个信息量充分的失败 + 1 次验证即收敛。

跨臂迁移（L2 换实现）只影响投影，L1 约束与 Θ 后验原样带走——§14.4-P1
的 robopal 对照实验即此机制的验收。

### 15.6 风险与防线

- **误分类割**：遥测签名不唯一时（stall 可能是"慢"也可能是"挡"），
  §15.2 表给出 competing cuts，按签名似然分配置信度，软收缩；连续
  同型失败提升签名唯一性（第一次 stall 二义，第三次同型 stall 后
  "慢"假设可由 z 轨迹匀速性证实）。
- **割的矛盾**：两个约束给出相交为空的后验 → 触发归因升级（记录
   contradiction，交集中取高置信约束，人工/agent 分析接口复用 §9
  任务卡机制）。
- ** sim2real**：Θ 在线辨识正是 sim2real 的接口——仿真里辨识出的
  μ 后验到真机继续收缩，而非从零开始。
- **复杂度**：割算子表是新增的单点知识源（与 §14.4-P0 的
  physics/constraints.py 同体：判据函数与割算子是一张表的两列），
  不引入新子系统。

### 15.7 与现有 Phase 的合并

| 现有件 | §15 后的归宿 |
|---|---|
| `policies/retry.py` 手工序列 | 退役 → 可行集后验采样（§15.4） |
| `reflection.py` if-elif | 退役 → 割算子表（§15.2），YAML 只剩 Θ 后验 |
| `_execute_chunk` 步级快照重试 | 保留，重试入口改由监视器 abort 触发（§15.3） |
| `ParamSpace` | 保留，从"范围裁剪"升级为"范围 ∩ Θ 后验" |
| `physics/constraints.py`（P0 计划） | = 运行时监视器 + 割算子表，P0 的实体改名 |
| EpisodeMemory（P2） | 存储单元从"成功参数"改为"Θ 后验 + 签名→割 的似然统计" |

落地顺序不变（P0→P3），但 P0 的交付物明确为：**约束判据+割算子+
运行时监视器三合一模块**，它一旦就位，spatial:4（预算割）、
spatial:9/goal:2（摩擦锥割）、z_delta 污染（Θ 后验替代裸 YAML 值）
三个现存病例应当同轮痊愈——作为 P0 的验收标准。


## 16. 认知层：假设-实验-判别-推导，一条循环统一执行/重试/学习/迁移（2026-09-23 三版）

> 动机：§14 回答"什么知识能泛化"（声明式），§15 回答"知识怎么更新"
> （对偶割）。但知识**怎么进来**的答案还不优雅——学习信号被动地等
> 失败送来，重试是对参数的重摇骰子，标定靠离线报告逐任务填裸值。
> 2026-09-23 一天的攻坚暴露了本质：6 个任务的修复全部是同一个
> 三步动作，由架构师手工执行——
> **判别**（F=0 还是 F>0？z 在动还是停了？）→ **归因**（到达极限/
> 几何阻挡/预算不足）→ **推导**（接受 / 修几何 / 加时）。
> 本节把这三步升格为系统机制，并指出：**判别子比约束更稀缺**——
> 约束可以现场推导，知道"此刻该看哪个观测量"才是经验。

### 16.1 核心重构：执行即实验，重试即实验设计

现状循环：`policy 选点 → skill 执行 → 二元成败 → 反思调参`。
学习信号是二元的（§15.3 已指出浪费），重试是盲搜（§15.4 已改良为
后验采样，但采样依据仍是"上一次失败了"，不是"哪个假设还没排除"）。

新循环（替换上述全部）：

```
 hypothesize  维护 competing hypotheses 栈（先验来自记忆库 Θ 残差）
 experiment   选下一个动作 = 在"推进任务"与"排除假设"间取最大信息/代价
 observe      判别子（§16.2）对实时遥测求值 → 证据 dict（不是二元成败）
 conclude     证据 → 割（§15.2）收紧 Θ / 测量值直接写入事实库 / 成功
 execute      结论重算约束可行集 → 下一个实验从可行集采样
```

关键升级有三：

1. **skill 返回证据，不返回成败**。descend 的返回值从
   `{success, reason}` 扩为 `{success, evidence: {f_trace, z_trace,
   z_rate, xy_drift_trace, clearance_min}}`。成功与失败同样进 Θ 后验
   ——一次干净成功的 descend 也测量了接触 z 真值。遥测零浪费。
2. **重试预算 = 实验预算**。每次失败先把假设空间切一刀（§16.2
   判别子），重试参数从"切剩下的假设 ∪ 推导式"生成——**不存在
   同一原因失败两次**：第二次相同签名 = 分类错误，触发矛盾升级
   （§15.6），而不是再烧一次预算。
3. **重试可能不再是重试**。判别子可能直接给出"这是 L2 可达性问题，
   参数怎么调都没用"——立即升级路径规划或上报，不浪费 5 次重试
   （spatial:4 若早十分钟判别出 F=0，就不会把 8 次尝试烧在
   k_descend 上）。

### 16.2 判别子（discriminator）：比约束稀缺的知识

判别子 = `(观测量, 判定规则, 假设空间的一个二分)`。它是**机器人
无关**的（观测量是物理量，不是臂专属信号），是记忆库里最该优先
迁移的东西。2026-09-23 实证过的判别子（每一行都救过至少一个任务）：

| 判别子 | 二分 | 2026-09-23 病例 |
|---|---|---|
| `contact_force(body) ≈ 0 vs >阈值` | 自由空间停滞（到达极限，可接受）vs 几何接触阻挡（真问题） | spatial:4 停沿口上方 22mm F=0 → 接受准则；goal:3/4 沿口 F>0 → 几何修 |
| `z_trace 匀速>0 vs 恒为 0` | 预算不足（慢型，加时有效）vs 真卡死（加时无效） | spatial:4（0.3mm/步）vs spatial:2 X 向蹭沿（0）——同为 "stall"，对策相反，不判别就会像 r9 那样把 5 次重试全烧错 |
| `lift 时 body_z 是否跟随 TCP_z` | 夹持成功 vs 夹空 | 全部 lift_no_grip 的第一刀 |
| `滑移方向 vs 重力方向夹角` | 摩擦锥违背（该滑：加夹持力/降速）vs 几何挤压（被挤飞：修放置点） | spatial:9/goal:2 place slipped——当前还没切这刀，所以 place_vcap 试错 8/8 无效 |
| `clearance 最小对的 pair_name` | 撞的是哪个障碍 | goal:3/4 above 卡柜顶 vs 卡桌沿，绕障侧不同 |
| `xy 漂移方向的时间一致性` | OSC 构型性漂移（可补偿）vs 目标点本身不可达（换点） | goal:3/4 xy_drift |

**教训条目**：jit（探索抖动）本身就是一个需要判别子护航的参数——
"候选点偏差"假设被排除后 jit 必须强制归零；精密几何（straddle 指
距-沿口间隙 < 2×jit）时 jit 物理不可行。r10 手工把 goal:3/4/5 的
jit 归零就是这条规则的先期手工执行。

### 16.3 主动探针（probe）：把"标定彩票"变成"运行时测量"

现状最丑的一角：contact_stop_band 靠离线标定报告逐任务填裸值
（0.066/0.108/0.12/…——TODO.md 有完整罪证），本质是承认"系统
到现场不知道该量什么"。探针 = 成本 < 一次失败预算的主动实验，
直接把 Θ 里的标量测出来：

| 探针 | 测什么（一次实验） | 杀死的彩票 |
|---|---|---|
| 慢降接触探针（vcap↓，F>阈值即停） | 接触 z 真值 → band = 实测短缩 + 裕度 | contact_stop_band 逐任务标定（全部任务，运行时免费） |
| 可达探针（指令深 z，读最大到达 z） | L2 到达极限（构型的函数，不是常数！） | spatial:4 的 22mm 靠人工诊断 |
| 摩擦探针（定力夹持 + 逐步切向加载） | μ 一次直接测得 | place slipped 反复试错（spatial:9/goal:2 各烧 8 次） |
| 几何核对探针（指距 vs 沿口半径） | straddle 可行性 + 最优偏置方向 | 容器方向投票抽签（09-22 的 bug 源） |

探针多数**就是执行本身**：慢降接触探针成功 = descend 已完成。
额外成本 ≈ 0。这正是"机器人可以问物理引擎问题"的 operational
形式——VLA 做不到这件事，它是开环答案机；本架构的物理引擎可以
被**查询**。

### 16.4 实验选择：学习速度的账

- 现状反思：每个参数独立二分搜索 → O(∏ᵢ log range) 次尝试，
  方向规则盲（k_descend 死亡螺旋的根源），无提前终止。
- §15 对偶割：O(k) 次信息量充分的失败（k = Θ 未知标量数，~3~5）。
- §16 探针 + 判别：μ/到达极限/接触 z **直接测量**，不算失败次数；
  剩下真需要排除的假设按"最小代价优先"序切 → **O(log H) 次实验**，
  H = 该签名下的竞争假设数（通常 ≤4）。

一个 LIBERO 任务的陌生场景预算估算：实例化（0，§15.5）+ 残差
检索（0）+ ≤3 个探针（多数与首 attempt 执行重叠）+ ≤2 次假设
排除 + 1 次验证 ≈ **个位数尝试**，与"8 次尝试内通过"的现有预算
同阶但不再依赖运气——这是"学的快"的量化定义。

### 16.5 "同一坑不摔两次"：系统级不变量

签名（判别子求值结果）→ 假设 → 对策 的三元组全部落库。
运行时不变量：**同一签名不得在无新证据的情况下重复同一种失败**。
违反即矛盾（§15.6），升级路径：① 判别子判错了（提升签名唯一性
检查）② 推导式错了（修约束/割行）③ 执行层没按结论做（查
ParamSpace 采样是否尊重后验）。这把"为什么又失败了"从玄学
变成可查询的三选一。

### 16.6 优雅陈述：系统 = 一条循环 × 四个注册表

```
循环： hypothesize → experiment → observe → conclude → execute
注册表（全部可插拔、机器人无关、逐行沉淀）：
  约束   constraints   §14.2 表 + derives（判据与推导）
  割     cuts          §15.2 表（证据 → Θ 半空间）
  判别子 discriminators §16.2 表（遥测 → 假设二分）
  探针   probes        §16.3 表（主动实验 → Θ 测量值）
```

小模型的插口随之统一（回应"可对接各种小模型"的原始诉求）：
感知小模型 → 判别子求值器；物理/几何模型 → 约束与推导行；
策略模型 → 假设排序器（experiment 步的 prior）；LLM → 矛盾升级
时的归因分析（§9 任务卡接口不变）。**没有小模型可用的格子，
退化为 §12.3 的解析推导或一次探针**——每格都有非学习兜底，
这就是"泛化边界拓展到小模型边界"的含义：小模型只负责它擅长的
那一格，格子本身永远有物理兜底。

反 hard-code 纪律与 §14.3 相同：表行是知识（可沉淀、可迁移），
循环代码是水管（一次写好不动）。新失败模式 = 新一行，不写新
if-else。

### 16.7 风险与防线

- **判别子误判的级联**：判别子错了，假设切错，后续全错。
  防线：判别子带置信度（观测量噪声已知时），低置信不切假设只
  记证据；探针结果可复核（接触探针的 F 阈值可从 L0 摩擦知识
  交叉校验）。与 §15.6 同构，不新增机制。
- **探针的物理副作用**：主动实验可能撞歪物体。防线：探针全部
  经 Phase B 快照保护（可恢复），且探针动作本身是低速小步进
  （§16.3 的设计约束）。
- **过度工程诱惑**：不要为"信息增益"上 POMDP/BayesOpt 全栈。
  最便宜可用序：先验排序 → 第一个能二分 top-2 假设的判别子 →
  切。信息增益公式只在假设 >4 时才值得算。
- **表膨胀**：四张表可能长到难维护。防线：行格式标准化
  （签名/判据/对策/失效边界/实证来源五列），失效行退役不删除
  （留实证出处）。§14.5 的"诚实失效边界"列同样适用于新表。
