# 03 · 技能库

> 对应代码：`darwin/agents/libero_skills.py`

## 1. 技能库是什么

项目用「Agent + 技能」的方式跑机器人操作任务：Agent 负责看懂任务、决定下一步做什么，技能库负责把「把杯子拿起来」「把抽屉拉开」这类要求变成一段段能在仿真里执行的动作。技能库是项目的主体——每个技能都是参数化的可复用动作单元，接收环境适配器和参数，返回执行结果；它不判断任务是否完成，也不决定先做哪一步，那是 Agent 和任务定义文件（记录一个任务的物体、初始状态与目标判断条件的规范文件）的职责；库里没有按任务写死的阈值，出现的数字只有四类来源：模型的几何与关节限位、执行时在线测出的量、求解器自身的精度参数、统一的统计约定。

一个技能的统一约定：

- **签名**形如 `skill(adapter, ...参数..., mem=None)`；`adapter` 是环境适配器，是技能访问仿真模型与观测的唯一入口，`mem` 是可选记忆字典，用来在同一个子目标的多次尝试之间保留状态。
- **返回值**是字典：成功为 `{"success": True, "measures": {...}}`，失败为 `{"success": False, "reason": ..., "mechanism": ..., "measures": {...}}`。`reason` 是给人看的失败原因，`mechanism` 是给程序看的失败分类（调用方按它决定下一步），`measures` 是数值细节（夹持力、位移量、末端位置等）。
- 例外是 `serve` 和 `goto`：成功返回 `None`，失败才返回上面那种字典。

## 2. 基础运动：`serve` 与 `goto`

签名：`serve(adapter, target, *, gripper, k, verify, budget, target_rot, kr)` 与 `goto(adapter, target, *, gripper, k, tol, timeout, target_rot)`（出于排版省略了默认值）。

`serve` 是位置伺服：闭环地一步步微调控制指令，让末端持续朝 `target` 靠近；给 `target_rot` 时同时伺服姿态。它以三种方式结束：

1. **到位**——调用方给了 `verify` 函数就按它判定；否则要求位置残差 ≤ `max(IK_TOL, 3σ)` 且姿态残差 ≤ `ROT_TOL`。σ 是本次动作在线估计的末端噪声，所以「到位」的标准是「残差进入了噪声范围」，而不是写死的距离。
2. **停滞**——每 `WIN` 步做一次窗口回归，看末端距离是否在缩小。连续几个窗口没有进展时按物理证据分类：接触力超出背景 3σ 记 `contact_blocked`（被挡住），关节几乎不动记 `ik_unreachable`（够不到）。这里刻意不设步数上限：慢而持续的进展应该走完，硬截断会把接近接触的最后几毫米截断。
3. **显式预算**——只有传入 `budget` 时才用步数上限，超了返回 `timeout`。

`goto` 是 `serve` 的兼容包装：`tol=None` 时原样调用 `serve`；给了 `tol` 就构造几何复核条件「末端到目标距离 ≤ tol」交给 `serve`；`timeout` 作为 `budget`。

底座之下还有一层路径工具：`corridor_plan` / `execute_corridor` 把一段位移拆成多条腿，逐腿到位再走下一段；`plan_arm_path` 在关节空间做随机采样运动规划，找一条不碰撞的路径；`execute_arm_path` 按固定间距细分路径后逐步执行，每一步都在真实物理状态上复查碰撞；`_reach_site` 把「到达一个接触点」打包成预抓取后退 → 关节路径 → 流式执行 → 事件驱动接近四段。

## 3. `grasp`：抓取

签名：`grasp(adapter, obj, cand=0, mem=None)`。把物体 `obj` 抓起来；任务无关，不针对某个物体写分支，所有决策都来自实时几何。

### 3.1 候选从哪里来

候选就是「可以怎么下手抓」的候选位姿，从两个来源轮流产出：

- **学习型抓取**（GraspNet，一个在抓取数据集上训练的网络）：对全场景点云（一堆表示场景表面的三维点）推理，输出一批抓取位姿；用全场景而非物体自身的点云，是为了让网络看到支撑面与周围物体。
- **分析解**：直接对物体外形求解的两种手法——`analytic_rim_pinch` 从口沿或薄壁处捏，`analytic_side_grip` 从侧面夹。

两类来源轮流产出而非先穷尽一类，是为了避免某一类里成串的坏候选把另一类的可行解饿死。生成后先过**三道粗筛**，都只看几何：

| 粗筛 | 条件 | 在挡什么 |
|---|---|---|
| 宽度 | 夹持宽度 ≤ 手的可达半开距 | 手张不开那么宽，根本夹不住 |
| 高度 | 抓取点不低于 `z_bottom + min(物体高/3, 3·tip_r)` | 指尖探到支撑面附近把物体撬翻 |
| 邻近 | 候选点落在目标包围盒外扩 `a_reach` 的范围内 | 其实是在抓旁边的东西 |

宽度分两档：第一档 `a_open + tip_r`（握得稳，优先出），第二档 `a_open + 2·tip_r`（挤压力度更大，排在后面）。失败过的候选记在 `mem["__failed__"]` 里，同一个重规划轮内不再试。

### 3.2 单个候选要过哪些关

任一关不过就换下一个候选：

| 关口 | 它做什么 | 在挡什么 |
|---|---|---|
| `site_filter` | 用逆运动学（由「手要到哪里」反推「每个关节角是多少」）求可行关节角，要求不引入新的自碰撞、与环境接触只发生在目标或其支撑物上 | 够得到但会撞到自己或环境的位姿 |
| `closure_gate` / `closure_marginal` | 把手指关节置到闭合限位做一次前向计算，实测指垫与目标的最深接触深度 | 浅于 `0.25·tip_r` 判「捏空」；落在 `0.25`~`0.75·tip_r` 的握持裕度不足，排到队尾 |
| `pregrasp` | 在抓取点后方找手完全张开也不碰东西的起点 | 没有可用的进入空间 |
| `approach_clear` | 检查从预抓取点到抓取点的直线接近是否畅通 | 接近段会擦碰；不通就换撤退方向重试 |
| `plan_path` | 规划一条从当前构型到预抓取点的不碰撞关节路径 | 无路可走 |
| `exec_path` | 按路径执行，实时复查碰撞 | 撞到自己、撞到目标以外的物体；目标的轻微擦碰允许，前提是它没被推动 |
| `approach` | 沿接近轴闭环伺服到抓取点，用几何到达 / 接触 / 停滞三个事件之一停止 | 只有指垫与目标的接触算到达；指身或手腕先碰到目标说明这个方位放不下这只手 |
| `reclose` | 第一次抬升没带起物体时，在原地再闭一次爪再试 | 腱传动手指在负载下会先伸展，第一次闭合行程没吃满 |
| `lift` | 竖直抬升至物体底面离开支撑面，同时要求手指与物体仍有接触力（≥ 0.5 N） | 物体被提起但力为零的假抓取 |

全部候选都试过仍不成，返回 `no_candidate`。

抓取成功后会把实测夹持几何写进 `mem[obj]`：`rel`（物体中心在末端下方多深）、`half_h`（物体半高）、`off_xy`（横向偏心）、`grasp_R`（抓取时的腕姿态），`place_at` 依赖这条记忆。成功的 `measures` 里有 `grasp_pt`（抓取点位姿）和 `lifted`（抬升量）。全场景候选还会按物体的几何签名缓存复用；签名没变而候选已穷尽时，再次调用会立刻返回失败。

## 4. `place_at`：放置

签名：`place_at(adapter, obj, target, predicate="On", mem=None)`。把手里抓着的物体放到 `target`，`predicate` 取 `"On"`（放到某个物体顶面）或 `"In"`（放进容器）。

1. **抬升越障**：按物体足印范围内最高的障碍几何，把物体竖直抬到它上方；抬升量按「扶正之后」的最低点预留——抓取时物体可能侧着，扶正后会垂得更低。
2. **计算放置点**：物体中心对准 `target` 中心，姿态直接取扶正姿态（接近轴朝下）。扶正不做成单独的步骤，姿态变化交给去往放置点的那段空中路径完成。
3. **闭环修正**：到位后按实测夹持几何修正一次放置点，把搬运途中的抓持滑移偏差消掉。
4. **下降并释放**：`On` 用「物体与目标接触」这个事件确认落座；`In` 直接释放。

两种释放方式不同：`On` 在保持下压伺服的同时开爪，用摩擦抵抗开爪的侧向推力；`In` 分几档慢开爪并留出物理沉降时间，让物体由重力落下，释放后再空走约 300 步等位置收敛。成功的 `measures` 里有 `tip_z`（末端放置高度）与 `dxy_to_target`（物体中心到目标中心的水平距离）；没有抓取记忆时会直接返回 `wrong_state`。

## 5. `push_to`：推动

签名：`push_to(adapter, obj, target, predicate="On", mem=None)`。不抓，直接把物体沿支撑面推到目标区域。这是抓取的**替代做法**：当 `grasp` 已确认几何上找不到可夹的候选时，同一个放置子目标退回推 / 拨。要点：

- **推进方向**每步重新计算，从物体当前位置指向目标区域中心（推动中物体会转、会偏，开环直线推进容易滑脱）。**触点**取物体包围盒背向目标那一侧的边缘，再退一个指尖半径。
- **手腕姿态**让开合轴竖直、接近轴水平，两根手指上下叠放，下指压住物体侧沿；先走到触点正上方一个**悬停高度**（高过场景里所有可动物体的顶面），再下探到按压高度。**高瘦物体**（高度大于 2 倍窄边宽）改用「低推」，把力作用线压低到接近支撑面，减小推翻力矩。
- **进给是一步步的闭环**：每步前进一步距，随时查询判断条件，满足就抬起收工。物体不动时先看指尖还接不接触物体——失去接触算「动作没做成」（`action_fail`），仍有接触才算「被挡住」（`contact_blocked`）；物体若翻倒或明显变形，按压几何按新的包围盒重建。

成功的 `measures` 里有 `moved`（推动的总距离）。

## 6. `articulate` 与 `toggle`：开合关节物体

这两个技能处理有铰链或滑轨的物体：抽屉、柜门是 `articulate`，旋钮是 `toggle`。共同点是先抓住一个作用点（把手、旋钮耳片），再沿关节自己的运动轨迹把它拖到目标位置。目标关节位置由环境给出；环境没给时取行程的极限。

```python
articulate(adapter, target, direction, strategy=0)   # "open" / "close"
toggle(adapter, target, direction, strategy=0)       # "turnon" / "turnoff"
```

### 6.1 找作用点

- **关节声明**（`_joint_decl`）：从模型读出关节类型（转轴或滑轨）、轴方向、轴上的点、行程范围。
- **作用体**（`_handle_geom`）：名字里带 `handle` / `knob` / `bar` 的几何优先；否则转轴关节取离轴最远、力臂最大的几何，滑轨关节取沿开合方向最外凸的面。
- **作用点与接近姿态**（`_articulate_site`）：转轴关节默认用「顶落式」，指尖从上方落到作用几何的顶沿；竖直转轴且顶面比指尖还窄（旋钮薄耳片）时，取按钮体顶面上离转轴最远的角点，按力臂从大到小做可达性预审取第一个可行的（不能用包围盒角点——旋转盒的包围盒角点会落在外面的空气里）；滑轨且轴接近水平（抽屉）时从正面水平接近、沿最薄截面方向捏夹，因为抽屉把手常上下叠放，从上方下探会先撞到上层把手。

### 6.2 沿关节轨迹跟随

`_follow_manifold` 是核心：抓住作用点后让它沿关节的运动轨迹走，转轴用绕轴旋转、滑轨用平移，这条轨迹也叫流形点。关键做法：

- **步距按手空间换算**：先求「关节每变化一单位、手在空间里移动多少」，再定出「手每次前进约 4 mm」对应的关节增量，而不是按角度固定加一步。
- **两种驱动方式**：旋钮用「指令领先」，每一步的指令角都略超过实际关节角（领先量有上限），静摩擦下要持续拖动，指令必须一直领先；柜门、抽屉用「等关节自己动」，指令角 = 实测角 + 一小步，这类较自由的关节若用领先指令抢跑，反而会让手甩开末端、永远进不了容差。非旋钮路径下关节几乎不动（位移不到行程的 5%）时，会在同一段里原地切换成「指令领先」再跟一次。
- **到位标准**：残差 ≤ `max(1% 行程, 3σ)`，且是双侧判断（残差的绝对值小于容差才算到达），否则「根本没动」会被误判成到达。
- **姿态跟转**：旋钮路径下腕姿态随关节角同步绕轴旋转，让指垫面与接触面保持平行，否则接触面在转、指垫不转会互相楔死。
- `goto` 报失败但关节其实已到位时，按同一个到位容差复核一次，判成功。

### 6.3 分段续程

一次拖不到位就分段做。`articulate` 首段跟完后如果判断条件未满足，最多再做 4 段：每段重新找把手作用点、重新接近、重新跟随，直到满足或行程到头。`toggle` 最多 6 段，每段转动量由实际接触阻挡决定、不是固定角度；某段位移不到行程的 5% 判真失败，剩余差不到 5% 就收尾复核（旋钮的关节摩擦会保持位姿，松爪后按新的耳片位置重抓续转）。成功后 `measures` 里有 `q`（结束时的关节值）、`q_goal`（目标值）、`steps`（用了多少步）。

## 7. 技能之间怎么组合

- **判断条件到技能的对应是固定的**：放置类（`On` / `In`）对应 `grasp` + `place_at`；开合类（`Open` / `Close`）对应 `articulate`；旋钮类（`Turnon` / `Turnoff`）对应 `toggle`。映射只看判断条件的种类，不看任务名字。
- **多个子目标按依赖顺序串行**：顺序由任务定义文件里的依赖关系确定，已满足的子目标会被跳过，所以重试时从世界现状接着做，不会重跑前面的步骤。
- **坐标通过世界状态传递**：技能只从适配器读当前的物体位姿、末端位姿和接触力，不做「上一个技能把坐标交给下一个技能」这种做法。
- **`grasp` 与 `place_at` 通过 `mem` 传递抓持几何**：`grasp` 成功后写 `mem[obj]`，`place_at` 用它推算放置点；没有这条记忆就直接返回 `wrong_state`。
- **同一个子目标内的重试是换手段，不是调参数**：`grasp` 失败就换下一个抓取候选；候选被确认耗尽时放置子目标改用 `push_to`；其余失败按当前世界现状重跑同一个子目标。
- **`serve` / `goto` 是所有技能的底座**：其他技能内部的每一步运动，最终都落到它们上面。

## 8. 关键参数表

数值取自 `darwin/agents/libero_skills.py` 顶部的常量区，以及函数里反复出现的固定比例。

| 常量 | 值 | 含义 |
|---|---|---|
| `GRIP_SITE` | `gripper0_grip_site` | 末端参考点的名字 |
| `IK_TOL` | 0.003 m | 逆解与几何「零距离」精度，同时是接触、落座的零判定 |
| `ROT_TOL` | `IK_TOL / 0.06` ≈ 0.05 rad | 姿态精度 |
| `CONF_K` | 3.0 | 噪声范围一律取 3σ |
| `TSTAT` | 2.0 | 判定「有进展」的斜率显著性门限 |
| `WIN` | 30 | 回归窗口的样本数 |
| `STATIONARY_MAX` | 3 | 连续无进展窗口的上限 |
| `K_SERVO` / `K_FINE` | 5.0 / 2.5 | 巡航增益 / 精细增益 |
| `IK_RESTARTS` / `PREGRASP_MAX` | 6 / 600 | 逆解多起点重启次数 / 预抓取点搜索的步数上限 |
| `EXEC_DQ` | 0.003 | 路径流式执行的点间距 |
| `RRT_STEP` / `RRT_MAX_NODES` | 0.15 / 6000 | 关节路径规划步长 / 节点上限 |
| `ANALYTIC_TRIES` | 12 | 每个分析解生成器的尝试上限 |
| `MU_PINCH` | 0.5 | 捏持摩擦系数；可捏壁面的倾角上限由它推出（约 0.447） |

| 固定比例 | 值 | 含义 |
|---|---|---|
| 闭合深度下限 | `0.25 · tip_r` | 浅于此判「捏空」 |
| 临界区间 | `0.25` ~ `0.75 · tip_r` | 握持裕度不足，排到队尾 |
| 夹持力门限 / 抬升行程上限 | 0.5 N / 0.30 m | 抬升时手指与物体仍需保持的接触力 / 超过即判失败 |
| 抬升柔度预算 | 4 轮 | 允许物体连续几轮不动还继续观察 |
| 推动步距 / 接触门限 | 0.01 m / 0.2 N | 每步前进的距离 / 低于此值算指尖失去接触 |
| 推动悬停高度 | 最高可动物体顶 + `3 · tip_r` | 越顶行走所需的净高 |
| 容器释放 | 分 4 档开爪，每档 25 步 | `In` 判断条件下的慢开爪 |
| 关节到位容差 / 续程段数 | `max(1% 行程, 3σ)` / 4 段或 6 段 | 跟随到位的标准 / 分段上限 |

## 9. 失败返回，以及调用方怎么用

技能失败时返回 `{"success": False, "reason": ..., "mechanism": ..., "measures": {...}}`。`reason` 是给人看的句子（例如「闭爪后物体未随抬升脱离」「推入受阻: 物体不随推进移动」），`measures` 带数值，便于记录和排查。调用方真正依赖的是 `mechanism`：

| `mechanism` | 含义 | 调用方通常怎么做 |
|---|---|---|
| `ik_unreachable` | 目标点的位置或姿态够不到，或被碰撞挡住 | 换一个抓取候选（换个接近方位往往就通了） |
| `contact_blocked` | 动作被物理阻挡（接触力异常或关节不动） | 世界已被动作改变，按现状重跑同一子目标 |
| `action_fail` | 手与物体失去接触，动作没真正作用到物体上 | 重跑同一子目标 |
| `no_candidate` | 抓取候选全部试过仍不成功 | 放置子目标改用 `push_to` |
| `timeout` | 达到显式步数预算仍没完成 | 重跑 |
| `wrong_state` | 前置状态不满足（例如没有抓取记忆就调 `place_at`） | 补齐前置步骤 |
| `perception_fail` | 目标名或关节信息解析不出来 | 检查任务定义 |

`measures` 的字段按技能不同：`grasp` 有 `grasp_pt`、`lifted`；`place_at` 有 `tip_z`、`dxy_to_target`；`push_to` 有 `moved`；`articulate` / `toggle` 有 `q`、`q_goal`、`steps`。规划侧按 `mechanism` 决定下一次执行的参数：`ik_unreachable` 换下一个抓取候选；其余把世界当作已经改变，用新的观测重跑同一个子目标。技能只负责如实报告发生了什么，重试策略留在调用方。
